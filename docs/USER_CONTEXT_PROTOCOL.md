# User context protocol — framework repo

**Purpose:** how agents decode Brent's "context" in **this repo**. Canonical law: [`37_NIGHTRAVEN.md`](37_NIGHTRAVEN.md) **§3** (five-step unclear input · understand before respond · interpretation framework) and **§4** (vocabulary layers) — this doc routes; it does not duplicate the protocol.

---

## Core mapping

| Brent says | It means | Not |
|------------|----------|-----|
| "add context" / pastes an idea | Vocabulary/overlay row + wire (intent ladder **memory** layer) | A code `*Context` type |
| "understand this concept" | Build mental model; explain before recommending (§3) | Summarize-only or jump to code |
| Telegraphic fragment | Compressed intent — run §3 five steps, answer the intention | Literal-words-only reading |
| "code it" / "implement" / "build" | Ship signal — drop to code (§2.8) | Implied by exploratory Q&A |

## Where context lands (this repo)

1. **Vocabulary** → [`NIGHTRAVEN_REPO_OVERLAY.md`](NIGHTRAVEN_REPO_OVERLAY.md) §1 — one canonical row per concept.
2. **Wire** → cross-links across rule · Bible · overlay · `AGENTS.md` · handoff (no duplication).
3. **Session record** → handoff **Recent sessions** (`+#`, newest first); Tier 2+ also changelog + learning log.
